# Agent instructions for quanto

These instructions are for agents working on this repository. They are not shipped with the package (the shipped codec authoring guide is `AUTHORING.md`). `DESIGN.md` is the source of truth for the design.

## Packages

- This is a bun workspace. The core, `quanto`, is `packages/quanto`. It's the protocol: codec contracts, definition helpers (`defineCodec`, `quantity`, `defineRange`, …), context, issues, composition and shared parsing primitives. It holds strong opinions that every codec conforms to, and it has no codecs. The codecs are a bootstrap, to use, copy and modify: the common ones are `@quantojs/common` (`packages/common`), quantities, numbers, percent, ratio, text, money, odds, CSS colors and ready-made formatters. Dates are a separate package, `@quantojs/datetime` (`packages/datetime`), and so are music, `@quantojs/music` (`packages/music`), addresses, `@quantojs/libpostal` (`packages/libpostal`), an external codec over libpostal, phone numbers, `@quantojs/libphonenumber` (`packages/libphonenumber`), over libphonenumber-js, coordinates, `@quantojs/geo` (`packages/geo`), and ring and shoe sizes, `@quantojs/sizes` (`packages/sizes`). `@quantojs/anything` (`packages/anything`) merges them all into one codec. A codec never goes in the core. New first-party codecs go in `@quantojs/common` when their behaviour is complete and settled (a unit table, a small parser, or a finished domain like money), and in a dedicated package when they're intentionally incomplete or still evolving, so their parse results are expected to change between releases. What goes in the core is what codecs share and must agree on. The React input is `@quantojs/react` (`packages/react`). The site is `apps/site`. The root is private: shared tooling and the repo docs.
- Codec packages, `@quantojs/common` included, import quanto only by name, through its public API (`quanto`, `quanto/quantity`, `quanto/formats`, `quanto/testing`), never by relative path into `packages/quanto/src`. If it needs something that isn't public, raise it as an API question. Codec packages don't depend on each other; the core's own tests use `@quantojs/common` as a dev dependency. The exception is `@quantojs/anything` (`packages/anything`), which merges the others into one codec and so depends on them; it isn't a codec package of its own, and nothing depends on it.
- `bun run typecheck` and `bun run build` at the root cover every package.

## Tests

- Never add unit tests unless the user explicitly asks for them, or a test is required to fix a bug.
- Fixtures are the exception. Codec fixture files (`fixtures.json`) are a special kind of unit test: they are the codec's spec. Every first-party codec requires one, and it should be extensive, covering the common inputs, locales, compound forms, every issue code the codec can produce, alternatives, parse context and formatting. Don't write tests of plumbing (that a factory returns a codec, that options are wired). Write the fixtures first, then the parser, as `DESIGN.md` describes.
- Run `bun run check` (typecheck and tests) before calling work done.
